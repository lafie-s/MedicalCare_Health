# 故障日志与自动重启

## 故障日志

服务目录的「故障日志」保存每次异常探测的北京时间、HTTP 状态、耗时（缺失显示无有效数据）、超时/连接错误码和采集中断。日志与探测结束及审计同事务保存，探测 ID 去重；最近 30 天、每服务最多 10000 条，与一天探测数据分开清理。GET /api/v1/services/:id/failure-logs 支持 20 条分页，按环境授权。历史故障不会从旧数据回填，升级后新故障开始保存。

不读取或保存 HTTP 响应正文、请求参数、Cookie、令牌和患者资料。Node 原始 error.message 不入库，仅允许明确网络/TLS 错误码；这不是业务异常全文日志平台。自动重启前从批准容器读取最近 5 分钟、最多 100 行 Docker 日志（命令 10 秒、最多 256 KiB），仅提取固定错误代码/异常类型集合并保存；原始文本不入库、不返回浏览器。未知业务消息及完整堆栈仍保留在业务系统既有日志设施中，后续如需全文检索须接入源端脱敏日志。

## 启用与触发规则

首页「自动重启」→ 选择服务，管理员填写原因并确认启用。缺少执行器时只读提示未配置，不能伪装成已启用。服务端校验员工身份、环境授权、管理员角色和 Origin；版本冲突与幂等 UUID 防止重复配置。停用不强杀已经发出的重启命令，但异步诊断后、命令发送前会再次检查停用状态。

仅启用后的新自动采集样本可触发。连续 3 次 HTTP 5xx、连接失败或超时，样本必须属于同一当前服务版本/目标指纹，间隔不超过两倍采集周期加 5 秒，最新样本不能过期或来自未来。成功、4xx、采集中断、手动探测、断档、配置变化或无数据都不构成连续故障。每次尝试后需新样本，冷却 10 分钟，每滚动小时最多 3 次；取消也保守计入次数。平台重启保留正式配置、配额、任务和日志，不自动重放中断任务。

服务停用、目标撤销、维护窗口有效、手动维护、发布任务运行或结果未知时暂停。发布与恢复在 SQLite 事务内互斥，自动恢复期间同样拒绝版本发布；不会同时修改同一组业务容器。

## 执行流程

1. 原子领取任务并写 started 审计，重复样本不产生新任务。
2. 重启前保存固定格式容器诊断摘要；读取失败记录不可用，探测故障日志仍保留。
3. 再次核对目标、服务版本、启用开关及维护状态，变化则取消。
4. 固定 docker restart --time 10 操作批准容器，45 秒命令超时。只允许 medicalcare-app / medicalcare-chat，不能传任意命令或容器。
5. 最多约 120 秒轮询容器健康，并真实探测批准 HTTP 目标；均通过才标记成功。命令失败、超时或健康未通过记为 unknown，锁住自动恢复与发布，管理员核对执行停止及实际网站状态后按任务 ID 解除锁定。重复核对同一已解除任务不重复写审计，也不会误解除后来任务。

结果独立于下一次运行指标采集，不能用任务成功伪造新的监控样本。界面每 5 秒读取最新任务；配置确认期间暂停刷新，失败保留草稿，缺失状态不当作正常。

## 正式部署

RECOVERY_CONFIG_PATH 指向部署机受控 JSON，格式见 config/recovery.example.json，serviceId 必须先登记且绑定正确的健康探测目标。容器列表只能从两个批准名称中选择。执行平台需要受控 Docker CLI 权限；公开演示绝不能挂生产 Docker socket。正式配置默认关闭，管理员明确启用后才运行；不要把示例 UUID 当作真实服务。

真实 Docker 执行器及 HTTP 探测已实现，本次没有在 MedicalCareWeb 生产执行重启。腾讯云公开平台使用模拟重启，点击「模拟连续故障」会按真实 30 秒间隔产生 3 个演示故障样本（约 1 分钟），经过同一阈值/配额/审计判断。此按钮只在 demo 后端可用，管理员权限，UUID 去重、单批互斥、重启后重置。

## 数据

failure_logs 保存独立故障；recovery_policy/recovery_changes 保存带版本配置及操作原因；recovery_tasks 保存触发探测 ID、状态、时间、诊断和结果。审计分类为自动重启，数据库快照包含这些表。采集器停止后等待恢复执行收尾；中断运行任务下次启动改为 unknown，不自行继续。
