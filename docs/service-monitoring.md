# 服务目录与探测接入

## 服务目录（F02）

管理员可在授权环境登记、编辑、启用及停用服务；运维人员及只读用户当前可查看服务配置。服务名、负责人、白名单目标和采集间隔均必填。每环境最多 100 个服务，列表完整展示；目标在同一环境不可重复登记。

配置保存在现有状态 SQLite 的 `services` 表，创建及修改与 `audit_events` 同事务提交。新增请求要求 UUID `idempotencyKey`，重试同一请求不会重复登记；不同请求内容复用键返回 409。编辑通过 `version` 防止覆盖并发修改，409 时刷新并重新打开表单。停用不删除服务历史。

接口：`GET /api/v1/services?environmentId=...`、`POST /api/v1/services`、`PATCH /api/v1/services/:id`。全部沿用现有身份、环境授权、同源写请求和限流校验。客户端只收到白名单目标 ID 与名称，不返回 URL 或固定 IP。

## 部署管理员配置白名单

在本地 `data/access-policy.json` 顶层配置 `probeTargets`。每条记录属于一个环境，由部署管理员审核目标后添加。示例只解释格式，不能直接视为真实 MedicalCareWeb 地址：

```json
{
  "id": "chat-ready",
  "environmentId": "local",
  "name": "聊天服务就绪接口",
  "url": "http://127.0.0.1:4400/health/ready",
  "address": "127.0.0.1"
}
```

仅允许 HTTP/HTTPS，禁止 URL 中出现用户名、密码、查询字符串和片段。`address` 必须为固定 IPv4/IPv6；URL 使用 IP 时必须与 address 一致。URL 使用主机名时，后续探测通过该地址固定连接，保留原始 Host 与 TLS 主机名校验，防止 DNS 解析变化扩大访问范围。

白名单没有默认生产地址。撤销目标授权后仍允许管理员停用对应服务，但不能继续启用该目标。首次接入应选择已确认无业务副作用的 GET 健康端点。

## HTTP 健康探测（F03a）

后端启动时启动单实例调度器，每轮结束后等待 5 秒，选择已启用且到期的白名单服务，最多并发 4 个请求。服务采集间隔可选 30、60、300 秒；自动与手动采集共用间隔和执行锁。配置启用不代表服务正常，必须查看采样结果。

管理员及运维人员可调用 `POST /api/v1/services/:id/probe`，要求 UUID `Idempotency-Key` 请求头、有效会话、环境权限及同源 Origin。只读角色返回 403。相同员工、服务与请求键复用结果，不重复发起网络请求；正在执行返回 202，完成返回 200，冷却期、停用、目标撤销和键冲突返回 409。接口每分钟最多 20 次请求；结果保存失败返回 503。页面不确定失败重试时保留请求键。

探测以 GET 请求连接白名单固定 IP，保留 Host 及 HTTPS 证书校验；不跟随重定向，不携带员工凭据，不保存响应正文。超时为 3 秒。2xx 表示探测通过，其他 HTTP 状态、连接失败及超时表示异常；运行中断为未知。耗时只统计到收到响应头，不等同于业务接口完整耗时或 P95。

服务列表接口返回最近完成采样、结果原因、采集时间及 5 分钟探测成功率。窗口为 `(当前时间 - 300 秒, 当前时间]`，按开始采集时间计算，只计入当前服务版本和目标配置的已完成有效样本；中断及运行中样本不参与成功率。无有效样本时成功率为 null。样本早于 `2 × 采集间隔 + 5 秒` 时显示过期未知；配置变更、目标撤销及无采样也不能显示正常。页面每 30 秒刷新，并每秒检查当前显示数据是否过期；弹窗或手动探测期间暂停后台刷新。

采样持久化于现有 SQLite 的 `probe_runs` 表，开始、完成均写审计。超过 10 秒的未完成执行在下一次申请该服务探测时标为中断，迟到结果不能覆盖。完成样本保留 24 小时，由调度器清理，因此探测幂等重放保障也以该保留期为界；审计不随样本清理。本实现适用于单实例小规模 HTTP 探测，多实例调度和长期时序存储尚未实现，不能直接套用总体技术方案的完整指标容量目标。

已使用真实本机 HTTP 端点完成自动、手动及界面验证；测试身份和服务是隔离 fixture。真实 MedicalCareWeb 员工授权与运行环境尚未联调，CPU、内存、业务错误率、趋势及告警均不在 F03a 完成范围。
